# Skill Repo Tracker v1.2.3

## 中文

v1.2.3 是可靠性、安全边界与发布验证修正版。它重点处理任务晚回流、备份目录信任边界和迁移失败回滚，同时移除三个从未生效的设置，并保持既有 SQLite 数据兼容。

### 更新内容

- **任务调度不再互相覆盖**：手工与定时任务共用 single-flight / generation coordinator。同一任务不会重入，较早一代的慢结果即使晚返回，也不能覆盖较新的状态；应用继续只在前台运行调度，不新增后台 daemon。
- **备份目录按仓库身份打开**：`open_backup_folder` 只接受稳定的 `repositoryId`。后端重新查询仓库根目录并执行 canonicalize，拒绝由前端传入任意路径，缩小文件系统访问边界。
- **清理无效设置并保持兼容**：界面和内部请求不再暴露 `concurrency`、`retryCount` 与 `cleanupKeep`。旧数据库中的对应键继续保留并被安全忽略，旧 SQLite 数据和升级路径无需破坏性删除。
- **追加式迁移与原子回滚**：数据库升级使用追加式迁移账本和事务边界；文件系统写入、备份与替换继续采用原子操作。SQLite、文件系统、Keychain 或 GitHub 请求失败时会保留明确失败状态，不会把半完成操作当作成功。
- **统一验证与发布门禁**：`npm run verify` 统一执行确定性检查；CI 另外验证 coverage、Rust MSRV 和 E2E。发布门禁从干净 commit 构建、完整签名 App、重新封装并校验 ad-hoc DMG，随后再核对公开 Release 的 commit、大小与 SHA-256。
- **依赖安全与发布日志加固**：锁定依赖已将 high severity 的 `quinn-proto` 公告修复到 `0.11.17`。另一个 medium severity 的 `glib 0.18.5` 公告仍在跟踪，但不在 macOS arm64 产品的激活依赖图中，本版不宣称安全告警已经清零。local phase 会原子发布一个不可变、权限为 `0700` 的 generation 目录，其中 `manifest.json` 和 `manifest.token` 均为 `0600`；命令只输出文件路径，不把 token 内容写入日志。这个 token 只是未签名的产物字段载体，不是凭据或发布来源证明，整个 generation 目录也不会作为 Release 资产上传。

### macOS DMG

本次 Release 只提供一个 Apple Silicon macOS 安装测试包：

- GitHub Release：`Skill.Repo.Tracker_1.2.3_aarch64.dmg`
- 本地构建：`Skill Repo Tracker_1.2.3_aarch64.dmg`

安装包采用 ad-hoc 签名，不是 Developer ID 签名，也没有经过 Apple notarization。首次启动若被 macOS 拦截，请在 Finder 中按住 Control 点击 App 并选择“打开”，或在“系统设置 -> 隐私与安全性”中选择“仍要打开”。技术用户也可以执行：


## English

v1.2.3 is a reliability, security-boundary, and release-verification patch. It focuses on stale task completions, backup-folder trust boundaries, and rollback on migration failures, while removing three settings that never took effect and preserving compatibility with existing SQLite data.

### Changes

- **Task runs no longer overwrite one another**: manual and scheduled runs share a single-flight / generation coordinator. The same task cannot re-enter, and a slow result from an older generation cannot replace newer state. Scheduling remains foreground-only; this release adds no background daemon.
- **Backup folders open by repository identity**: `open_backup_folder` accepts only a stable `repositoryId`. The backend resolves the repository root again and canonicalizes it, preventing the frontend from submitting an arbitrary filesystem path.
- **No-op settings removed without data loss**: `concurrency`, `retryCount`, and `cleanupKeep` are no longer exposed by the UI or internal requests. Their legacy SQLite keys remain in place and are safely ignored, so existing databases and upgrade paths require no destructive cleanup.
- **Additive migrations and atomic rollback**: database upgrades use an append-only migration ledger and transaction boundaries, while filesystem writes, backups, and replacements retain atomic behavior. SQLite, filesystem, Keychain, or GitHub failures remain explicit and cannot turn a partial operation into a reported success.
- **Unified verification and release gates**: `npm run verify` is the deterministic validation entry point. CI additionally checks coverage, the Rust MSRV, and E2E flows. The release gate builds from a clean commit, signs the complete app, repackages and validates the ad-hoc DMG, and then reconciles the public Release commit, size, and SHA-256.
- **Dependency security and release-log hardening**: the lockfile now carries `quinn-proto 0.11.17`, resolving its high-severity advisory. A separate medium-severity advisory for `glib 0.18.5` remains tracked but is not active in the macOS arm64 product dependency graph, so this release does not claim that all advisories are cleared. The local phase atomically publishes an immutable `0700` generation directory containing `0600` `manifest.json` and `manifest.token` files, and prints only their paths, never the token contents. That unsigned artifact-field carrier is neither a credential nor release provenance, and the generation directory is not uploaded as a Release asset.
