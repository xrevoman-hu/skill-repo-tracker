# Skill Repo Tracker v1.2.4

## 中文

v1.2.4 是 Skill 更新可靠性修正版。它修复少数远端 Skill 在同一目录同时包含同名词干的文件和子目录时，ZIP 下载侧与临时目录复验侧采用不同排序语义，导致内容完全一致却被判定为哈希不匹配的问题；同时修复较大源码 ZIP 被普通 GitHub API 的 30 秒预算过早中断的问题。

### 更新内容

- **统一 canonical Skill 摘要**：ZIP 扫描和目录复验都只纳入常规文件的相对路径与内容字节，并按相对路径组件排序。`topic.md` 与 `topic/...` 等同词干路径现在会在两侧得到一致摘要。
- **严格兼容 v1.2.3 旧摘要**：旧摘要只在远端 SHA 与已记录 SHA 完全相同、且本次下载内容独立复算命中 legacy digest 时迁移。迁移后只保存 canonical digest，不会放宽后续校验。
- **保留冲突处理状态**：已经确认的本地自定义和等待用户处理的冲突会随摘要编码安全迁移，不会重新打开已处理事项，也不会生成重复任务。
- **无关摘要继续拒绝**：如果已记录摘要既不匹配 canonical digest，也不匹配本次下载独立复算的 legacy digest，更新仍然 fail closed，且不会修改本地 Skill 文件或元数据。
- **较大源码 ZIP 可完整读取**：源码 ZIP 使用独立且有界的 120 秒完整请求预算，31 MB 等较大 Skill 仓库不再被普通 GitHub API 的 30 秒预算过早中断；普通 API 与 10 秒连接预算保持不变。
- **补齐公开入口回归测试**：新增从 Tauri commands、Skill 列表、任务列表和冲突命令出发的更新、拒绝、已处理自定义与待处理冲突覆盖，并把长期边界写入文件系统 Rule。

## English

v1.2.4 is a Skill update reliability patch. It fixes a false mismatch that could occur when a remote Skill directory contains file and subdirectory paths with the same stem: ZIP scanning and temporary-directory verification previously used different ordering semantics even though the content was identical. It also prevents larger source ZIP downloads from being cut off by the regular GitHub API's 30-second request budget.

### Changes

- **One canonical Skill digest**: ZIP scans and directory verification include only regular-file relative paths and content bytes, ordered by relative path components. Same-stem paths such as `topic.md` and `topic/...` now produce the same digest on both sides.
- **Strict v1.2.3 legacy compatibility**: a legacy digest migrates only when the remote SHA exactly matches the recorded SHA and the freshly downloaded content independently recomputes to that legacy digest. Only the canonical digest is stored after migration.
- **Conflict decisions remain stable**: handled local customizations and pending user conflicts migrate safely with the digest encoding, without reopening handled work or creating duplicate tasks.
- **Unrelated hashes still fail closed**: if recorded metadata matches neither the canonical digest nor the independently recomputed legacy digest, the update is rejected without changing local Skill files or metadata.
- **Larger source ZIPs can finish**: source ZIP downloads use a separate bounded 120-second full-request budget, so larger Skill repositories such as the observed 31 MB archive are not cut off by the 30-second regular API budget. Regular API requests and the 10-second connect budget remain unchanged.
- **Regression coverage at public seams**: new tests exercise update, rejection, handled-customization, and pending-conflict behavior through Tauri commands, Skill/task listings, and conflict commands. The long-term digest boundary is recorded in the filesystem Rule.
