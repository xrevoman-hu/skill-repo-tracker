# Skill Repo Tracker v1.3.0

## 中文

v1.3.0 新增独立的仓库备份许可，方便继续关注仓库而不保存其源码快照。

- 已追踪 GitHub 仓库详情新增“允许备份”，默认开启。关闭表示“无需备份”，继续保留追踪、检测更新、README 与历史快照。
- 行选择与备份许可独立。即使被外侧勾选，关闭项也不会进入单仓备份、备份选中、备份有更新、前台调度或旧任务重试；数量和确认清单采用相同规则。
- 后端在入队、下载后和提交时核对许可。已发出的下载不能撤回，但关闭后阻止其提交为新快照，保留旧备份。
- 数据库追加迁移，既有仓库默认允许备份。检测与重新追踪保持偏好；新迁移包保存偏好，旧包缺字段不会重置已有仓库的选择。
- 此偏好只控制整仓源码 ZIP 备份；Skill 更新、同步和删除保护所需的安全备份保持原行为。
- 公共 `AGENTS.md` 索引项目架构规则，本机约定与资料说明保存在 Git 忽略的 `AGENTS-local.md`。
- 将 `rustls` 锁定到 `0.23.45`，并更新其所需的 `rustls-webpki 0.103.15`，修复 `RUSTSEC-2026-0285` 的 TLS 1.3 握手边界问题；不声称该漏洞已被实际利用。
- 安全审计按真实 RustSec 漏洞结构保留公告编号与包版本，避免把漏洞显示成 `unknown`；漏洞仍会阻止发布，既有风险账本与失败规则保持不变。
- 将开发测试依赖 `undici` 从 `8.10.1` 更新到 `8.10.2`，处理 npm 审计发现的高危公告；该依赖不进入桌面应用的运行时代码。

首次启动会追加数据库迁移。升级前请退出旧版并备份应用数据目录；如需降级，须恢复升级前的数据副本，旧版不能直接写入升级后的数据库。

## English

v1.3.0 adds a separate repository backup preference so you can keep following a repository without storing its source snapshots.

- Tracked GitHub repositories now have an enabled-by-default Allow backup checkbox. Disabling it retains tracking, update detection, README access and existing snapshots.
- Row selection is independent. Disabled repositories are excluded from individual, selected, updated, foreground-scheduled and retried backups, including their counts and confirmation lists.
- The backend checks permission before queuing, after downloading and during commit. A request already sent cannot be recalled, but disabling backup prevents a new snapshot from being committed and retains previous backups.
- An additive database migration enables existing repositories by default. Checks and re-tracking preserve preferences. Migration exports retain the preference; older imports with no field preserve the existing choice.
- The preference applies only to repository ZIP snapshots; protective backups for Skill updates, publication and deletion retain their existing behavior.
- Public `AGENTS.md` indexes project architecture rules, while machine-specific conventions live in Git-ignored `AGENTS-local.md`.
- Pins `rustls` to `0.23.45` with its required `rustls-webpki 0.103.15` update to address the TLS 1.3 handshake boundary issue in `RUSTSEC-2026-0285`; this does not claim the vulnerability was exploited.
- Security auditing now reads actual RustSec vulnerability records without losing advisory IDs and package versions to `unknown`. Vulnerabilities still block release; the existing risk ledger and failure rules remain unchanged.
- Updates the development/test dependency `undici` from `8.10.1` to `8.10.2` for the high-severity npm audit findings; it is not part of the desktop application's runtime code.

First launch adds a database migration. Quit the previous app and back up its application data directory before upgrading. To downgrade, restore the pre-upgrade data copy; older apps cannot write directly to the upgraded database.
