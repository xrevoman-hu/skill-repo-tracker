# 数据与安全 Rules

- 原 GitHub token 只进 Keychain；禁止写入普通 SQLite、日志、文档、fixture、ZIP 或迁移包。
- ADR 0010 的凭据 E0 使用独立 SQLCipher 库保存虚构秘密与附件；不改普通 SQLite/导出包边界。
  主密码不持久保存；独立 Agent 码只进固定凭据 Keychain namespace，不能作为库解密密钥。
  后端交付前重验解锁/共享状态；准备中的结果不可越过锁定或撤权。产品日志/错误不得含秘密。
- ADR 0012 的正式库创建为空，记录与原始文件字节只进独立 SQLCipher；人工秘密读取绑定
  主密码验证后的记录、版本和会话代次。失焦、离页、切记录、关抽屉和锁库使代次失效，
  后端在交付/剪贴板写入前再验；省略秘密字段表示保留，明确清除与原样替换分别处理。
  秘密剪贴板只按本次写入的系统变更标识及内容归属条件清除，不删除后一次相同文本。
- fixture 必须脱敏且虚构，不能复制用户目录或真实 GitHub 返回。
- 导出提示词正文前明确说明明文边界并二次确认。
- SQLite schema 先执行旧幂等升级，再记录编号迁移；已发布迁移只追加不重写。旧应用遇到
  未知的未来 core migration 或更高的 Prompt `user_version`，必须在任何持久 PRAGMA/DDL
  前拒绝打开，不能在更高版本 schema 上继续写入。
- 仓库备份偏好随追加迁移默认开启，检测或重复追踪不得重置。迁移导出保留偏好；历史迁移包
  缺少 `backupEnabled` 时，新仓库默认开启、已有仓库保留偏好，显式值按导入内容合并。
- 文件系统或事务在最后一步发生可观察失败时，也必须回滚到调用前可读状态；硬崩溃的
  跨存储残留按 ADR 0003 处理，禁止用递归扫描自动删除未知目录。
- Keychain 与 SQLite 的联合更新必须记录调用前凭据状态；数据库 statement/commit 失败时
  执行补偿并用回归测试覆盖，补偿错误不得泄露 token。
- Keychain 读取失败不能降级成“未配置”；删除失败时不得先清理 SQLite 元数据。底层
  Keychain 错误只映射为稳定错误码和脱敏标签，不把 adapter 原文返回给 UI。
