# ADR 0003：文件锁与原子替换

- 状态：Accepted
- 决策：写入或恢复先在目标同一文件系统创建临时内容，完整校验后再原子替换；跨进程
  操作使用可恢复的锁和明确超时。
- 原因：直接覆盖在崩溃、磁盘满或并发操作时会留下“看似存在、内容已损坏”的状态。
- 备份协议：备份根和本次唯一目录都持有 Unix directory fd，并记录 device/inode；所有
  ZIP、manifest 和 task log 只以 `openat(O_EXCL|O_NOFOLLOW)` 创建，ZIP 在同一目录内以
  macOS `renameatx_np(RENAME_EXCL)` 发布。提交 SQLite 前重新核对根目录和子目录身份，
  repository 更新必须恰好命中一行；只有事务 commit 成功后才保留目录。
- 失败清理：只对本次进程明确创建并记录的文件执行 `unlinkat`，最后对已核对身份的空目录
  执行非递归 `AT_REMOVEDIR`。禁止对猜测出的路径调用递归删除，也禁止扫描未知
  `backup-*` 后自动清理。
- 已知物理边界：文件系统与 SQLite 没有共同事务。`SIGKILL`、断电或进程在 commit 边界
  消失，仍可能留下未登记的唯一备份目录；最后一次身份核对后，拥有同等文件权限的外部
  进程仍可能再次替换目录。现有设计保证正常错误、取消和可观察竞态 fail-closed，不宣称
  跨文件系统/数据库的绝对原子性。未来若增加 orphan 恢复，必须依赖追加式、不含秘密的
  操作账本和用户可见确认，不能靠名称猜测或递归删除。
- 后果：失败路径必须测试旧内容仍可读、临时文件被回收、晚失败不会提交 SQLite 事务，
  并覆盖符号链接、目录替换、statement/commit 失败和任务取消。
